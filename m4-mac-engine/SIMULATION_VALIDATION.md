# シミュレーション妥当性検証レポート

## 現在のシミュレーション方式の問題点

### 1. データの問題
- **デモデータのみ使用**: 実際のJRDBデータを使用していない
- **結果の決定方法**: `IDM + ランダムノイズ(-5～+5)`で順位決定は現実的ではない
- **オッズ生成**: 固定値やランダム値で、実際の市場を反映していない

### 2. 予測モデルの問題
```python
# 現在のデモ予測（simulator.py 108-110行）
idm = horse.get('idm', 50)
win_prob = (idm - 30) / 60 * 0.3  # 0-0.3の範囲に正規化
```
- **単純すぎる予測**: IDMのみを使用した線形変換
- **特徴量の未活用**: 30個の特徴量を定義したが使用していない
- **学習なし**: MLモデルは存在するが、デモデータでは学習できない

### 3. バックテストの問題
- **過学習リスク**: 同じ生成ロジックのデータで評価
- **市場の複雑性欠如**: 実際の競馬の複雑性（馬場状態、展開、調子など）が反映されていない

## なぜ還元率が高く出るのか

### 1. 予測と結果生成の相関
```python
# データ生成（jrdb_fetcher.py 214行）
sorted_horses = sorted(horses, key=lambda x: x['idm'] + np.random.normal(0, 5), reverse=True)

# 予測（simulator.py 108-110行）
win_prob = (idm - 30) / 60 * 0.3
```
→ **IDMが高い馬が勝ちやすく、予測もIDMベース** = 高い的中率

### 2. オッズの非現実性
- 実際の市場では人気馬のオッズは低い
- デモデータではIDMとオッズの逆相関が弱い
- 結果：高配当を高確率で的中させやすい

### 3. ランダム要素の範囲
- ±5のランダムノイズは小さすぎる
- 実際のレースはより大きな不確実性がある

### 2. より現実的なシミュレーション
```python
def generate_realistic_result(horses):
    # 人気（オッズ）を考慮
    popularity_weights = [1/h['odds'] for h in horses]
    
    # 能力値の分散を大きく
    abilities = []
    for h in horses:
        base_ability = h['idm'] / 100
        # 調子、展開、相性などのランダム要素
        random_factor = np.random.normal(0, 0.3)
        abilities.append(base_ability + random_factor)
    
    # 確率的に順位決定
    probabilities = softmax(abilities * popularity_weights)
    return np.random.choice(horses, p=probabilities)
```

### 3. 適切な評価方法
- **クロスバリデーション**: 時系列を考慮した分割
- **実オッズとの整合性**: 人気順とオッズの相関を強化
- **複数シナリオ**: 異なる条件でのシミュレーション

## 結論

現在の94%還元率は以下の理由で**過大評価**されている可能性が高い：

1. **予測と結果生成が同じロジック（IDMベース）**
2. **オッズが非現実的（人気馬でも高配当）**
3. **不確実性が過小評価（±5は小さすぎる）**

### 推奨アクション
1. JRDBの実データ使用を優先
2. デモモードでもより現実的なデータ生成
3. 評価基準の見直し（実際の競馬場の還元率75%を基準に）

### 期待される現実的な還元率
- **初期段階**: 65-70%（ランダム予測より少し良い）
- **改善後**: 75-80%（プロの予想屋レベル）
- **最適化後**: 80-85%（システマティックトレーディングの上位層）
